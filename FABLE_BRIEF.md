## 0. Контекст проекта — прочти прежде чем писать код

**Что такое Folio.** Веб-приложение для абитуриентов, поступающих за рубеж: конструктор портфолио (Common App–style), честный AI-фидбек, реальные шансы поступления, база олимпиад/конкурсов. Позиционирование — «no glaze», честные оценки без лести. Целевой рынок сейчас — СНГ/Казахстан.

**Стек и соглашения (соблюдай их, не тащи новое без нужды):**
- Next.js 16 (App Router) · React 19 · **чистый JavaScript, без TypeScript** (файлы `.js`, есть `jsconfig.json`, алиас `@/`).
- Firebase (Auth через Google-popup + Firestore) — деградирует до localStorage-only, если env не заданы (`lib/firebase.js` возвращает `null`, всё продолжает работать).
- Vercel хостинг. Держи всё в рамках **бесплатных тарифов** (Firebase Spark, Vercel Hobby). Не добавляй платные зависимости/сервисы без явной пометки «опционально».
- Стилизация: инлайн-стили в компонентах + дизайн-система на CSS-переменных в `app/globals.css`. **Не подключай Tailwind/UI-киты.** Используй существующие токены: `--bg #f6f4ee`, `--surface`, `--ink`, `--primary #4585d9` (бренд-синий), `--accent #c08a2d` (**золото — зарезервировано под Premium/платное**), `--good/--warn/--bad`, шрифты `--display` (Days One), `--display-ui` (Poppins), `--sans` (Inter). Классы `.wrap .card .card-pad .btn .btn-primary .btn-ghost .btn-gold .pill .eyebrow .muted` уже есть — переиспользуй.
- AI: `lib/ai.js` — провайдер-агностик с фолловером **Groq → OpenRouter → Gemini** и in-memory кэшем. Ключи в `.env.local`. **Gemini-аккаунт ограничен `AQ.`-ключами (~20 запросов/день)** — Gemini НЕ должен быть в горячем пути, основной провайдер = Groq. API-роуты: `app/api/enhance/route.js` (переписывает одну запись), `app/api/feedback/route.js` (фидбек по всему портфолио). `runtime = 'nodejs'`.

**Ключевые файлы, которые ты будешь трогать/расширять:**
- `lib/store.js` — персистентность портфолио (сейчас localStorage-first + опциональный Firestore-sync в `portfolios/{uid}` как `{ data, updatedAt }`).
- `lib/auth.js` — `useUser()`, `signInWithGoogle()`, `signOut()`.
- `lib/firebase.js` — `getDb()`, `getFirebaseAuth()`, `isFirebaseConfigured()`.

**Правила безопасности:** никогда не свети AI-ключи на клиент (всё через `/api/*`). Не ломай текущий localStorage-only режим (без Firebase-env приложение должно продолжать работать вхолостую).

## A. Бэкенд-хардненинг (делай первым — без этого нельзя пускать трафик)

### A1. Rate-limit на AI-роуты — ✅ УЖЕ СДЕЛАНО (не переделывай)
Реализовано в `lib/ratelimit.js` и подключено в `app/api/enhance` и `app/api/feedback`. Детали:
- Pluggable-бэкенд: **in-memory по умолчанию** (ноль настройки) + опциональный **Upstash Redis**, если заданы `UPSTASH_REDIS_REST_URL` и `UPSTASH_REDIS_REST_TOKEN` (durable между serverless-инстансами). Fail-open при сбое бэкенда. Выбран этот путь вместо Firestore, т.к. серверная запись в Firestore требует Admin SDK + service-account — лишняя настройка; Upstash — чище для serverless и включается одним env.
- На каждый эндпоинт: burst-окно + дневной cap, ключ по IP (`x-forwarded-for`). Текущие лимиты (в константах `LIMITS` в каждом роуте): enhance — 8/мин + 40/сут; feedback — 4/мин + 20/сут.
- Превышение → HTTP **429** с дружелюбным `{ error }` (клиент уже показывает `data.error`) + заголовок `Retry-After`. Проверено вживую: per-IP изоляция, отдельные корзины на эндпоинт.
- **Что тебе (Fable) нужно доделать по мере появления новых платных фич:** когда добавишь `/api/essay` и `/api/counselor` (раздел F), оберни их тем же `enforce(request, name, LIMITS)`; для этих тяжёлых фич лимиты должны зависеть от плана (free — демо-затравка, pro/business — щедро), см. J2. Если введёшь серверную аутентификацию (проверку Firebase ID-токена), добавь ключ по `uid` в дополнение к IP.
- Кэш ответов в `lib/ai.js` (in-memory дедуп) оставлен как есть. Вынос кэша в durable-стор — по-прежнему «опционально».

### A2. Firestore-first данные + миграция
Сейчас `lib/store.js` localStorage-first. Для аккаунтов, шеринга и counselor-доступа нужен **Firestore-first, когда пользователь залогинен**, с локальным кэшем как ускорителем/офлайном:
- Залогинен → источник истины = Firestore-документ портфолио; localStorage = кэш (оптимистичные апдейты, дебаунс-запись как сейчас ~900мс).
- Разлогинен / Firebase не сконфигурен → как сегодня, localStorage-only.
- **Миграция:** при первом входе, если в облаке пусто, а в localStorage есть реальные данные (`hasContent`), засеять облако локальным профилем (эта логика частично есть — сохрани и укрепи её, не потеряй данные существующих пользователей).
- Сохрани текущую защиту от «пустой кэш свежего устройства затирает облако» (`cloudReady` guard).
- Сохрани `sanitizePortfolio()` (чистка junk) в пути загрузки.

## B. Роли и организации (ядро B2B — продумай тщательно)

Владельцу нужно, чтобы Folio помогал **школам и консультантам по поступлению** в работе. Спроектируй так, чтобы это было понятно и надёжно. Опиши итоговую модель в отчёте.

### B1. Модель данных (Firestore)
Добавь коллекции (имена — предложение, можешь улучшить, но опиши что выбрал):
- `users/{uid}` — профиль пользователя платформы: `{ role: 'student' | 'counselor' | 'orgAdmin', orgId?: string, displayName, email, createdAt }`. Роль по умолчанию `student`.
- `orgs/{orgId}` — организация (школа или консалтинг-практика): `{ name, type: 'school' | 'practice', ownerUid, joinCode, plan: 'free'|'pro', seats, createdAt }`. `joinCode` — короткий человекочитаемый код (например `FOLIO-7KQ2`) для приглашения.
- `portfolios/{uid}` — расширь: добавь `orgId?`, `counselorId?`, `shareId?`, `isPublic?` (существующее поле `data` не ломай).
- `orgs/{orgId}/members/{uid}` — членство (роль внутри орга, статус). Используется правилами для проверки доступа.
- `portfolios/{uid}/comments/{commentId}` — комментарии counselor’а ученику: `{ authorUid, authorName, text, section?, createdAt, resolved }`. Видны ученику.

### B2. Три сценария подключения — реализуй все, опиши в отчёте «как владелец передаёт продукт»

**Как владелец (ты) заводит клиента-школу/консультанта:**
- Сделай `/counselor/new` (или `/start-org`) — самостоятельное создание рабочего пространства: залогиненный пользователь жмёт «Я консультант / школа», вводит название → создаётся `org`, он становится `orgAdmin`/`counselor`, генерируется `joinCode` и ссылка-приглашение `/<origin>/join/{joinCode}`.
- Плюс скрытый founder-admin путь: страница `/admin/orgs` (доступ только по списку email из env `FOLIO_ADMIN_EMAILS`), где владелец может вручную создать орг, выставить план (`free`/`pro`), лимит мест — чтобы «условно передавать» доступ вручную при продажах.

**Как ученик подключается к counselor’у (два пути):**
1. **По ссылке/коду от counselor’а:** ученик открывает `/join/{joinCode}` → логинится Google → его портфолио привязывается (`portfolios/{uid}.orgId/counselorId`, запись в `orgs/{orgId}/members`). Экран подтверждения «Ты подключаешься к <название>. Твой ментор будет видеть твоё портфолио и оставлять комментарии. Продолжить?».
2. **Из настроек ученика:** в портфолио — блок «Подключить ментора» с полем ввода кода. Тот же результат.
- Ученик должен видеть, кто его ментор, и иметь возможность **отключиться** (удалить связь). Прозрачность доступа обязательна.

**Как school-admin добавляет counselor’ов:** в `orgs/{orgId}` есть свой invite-код для менторов (роль при вступлении = `counselor`). Отделяй код «для менторов» от кода «для учеников» (или один код + выбор роли админом при подтверждении — на твоё усмотрение, опиши выбор).

### B3. UX-правила
- Всё завязано на текущий Google-логин (`lib/auth.js`). Роль подтягивай из `users/{uid}` после входа; создавай `users/{uid}` при первом логине с ролью `student`.

## H. Firestore Security Rules (`firestore.rules`) — критично для B2B

Обнови правила под новую модель. Требования:
- `users/{uid}`: читать/писать может только сам пользователь (роль/план менять с клиента нельзя повышать в premium — **план/роль выставляются только сервером/админом**; продумай: либо правила запрещают клиенту менять `plan`/`role`, либо эти поля живут отдельно и пишутся только через доверенный путь).
- `portfolios/{uid}`: владелец — read/write. **Counselor того же орга — read** (проверка через `get(/databases/.../orgs/{orgId}/members/{counselorUid})` и совпадение `orgId`). Публичного чтения `portfolios` быть НЕ должно.
- `portfolios/{uid}/comments`: создавать может counselor орга; читать — владелец и counselor’ы орга; ученик может пометить `resolved`.
- `orgs/{orgId}`: читать — члены; писать — только `ownerUid`/orgAdmin. `members` — добавление контролируемо (по joinCode-флоу; продумай безопасный способ вступления — например Cloud Function или правило, проверяющее код; если без функций сложно, опиши компромисс).
- `shares/{shareId}`: **публичное чтение разрешено**, запись — только владелец исходного портфолио.
- `rate_limits/*`, `ai_cache/*`: клиент не читает/не пишет (пишет только сервер через Admin/серверный доступ). Если серверные роуты используют клиентский SDK — учти это и опиши в отчёте (возможно потребуется Firebase Admin SDK с service-account env для серверной записи в обход правил; пометь как ручной шаг для владельца).

> Правила, требующие `get()` на членство, — самая тонкая часть. Напиши их аккуратно, прокомментируй, и в отчёте дай **пошаговую инструкцию владельцу**: что вставить в Firebase Console и какие ручные действия нужны (индексы, service-account для сервера, если решишь его использовать).

## J. Тарифы и гейтинг (3 плана) — монетизация

Folio монетизируется тремя тарифами. **Базовые AI-функции остаются бесплатными для всех** (иначе нет воронки); платят за глубину (абитуриент) и за B2B-слой (бизнес).

### J1. Три тарифа

**1) Free (Базовый) — бесплатно, для любого абитуриента, без карты:**
- Конструктор портфолио, шансы поступления, база `/discover`.
- **AI-ревью (`/api/feedback`) и AI-полишинг записей (`/api/enhance`) — бесплатно**, но с дневным лимитом (rate-limit из A1).
- Демо-затравка платных фич: 1 разбор эссе + несколько сообщений AI-канслеру, дальше — апселл.
- Публичная share-ссылка с меткой «Made with Folio».

**2) Pro (для абитуриентов) — платный (индивидуальный):**
- Всё из Free без жёстких лимитов (щедрые лимиты на ревью/полишинг).
- **AI-канслер** (чат-ассистент, F2) — полный доступ.
- **AI-коуч по эссе** (F1) — полный доступ.
- **PDF-экспорт** без вотермарка (E).
- Кастомная shareable-ссылка без метки (D).
- Расширенный список вузов / приоритетная модель шансов, календарь дедлайнов (если делаешь) — как «приятные» добавки Pro.

**3) Business (для школ и консультантов) — платный, дороже (за место/за орг):**
- **Всё из Pro для каждого подключённого ученика.**
- **Counselor/school дашборды** (C): ростер, флаги, read-only портфолио, комментарии.
- Мульти-ученик, роли, орг-управление, экспорт когорты в CSV.
- **«Кайф для бизнеса» — сделай B2B ощутимо ценнее**, чтобы оправдать цену: 
  - **White-label / брендинг**: логотип и название школы на публичных портфолио учеников и в PDF.
  - **Аналитика когорты**: распределение по бэндам, средняя completeness, «кому нужно внимание», динамика.
  - **AI-ассистент для counselor’а**: «сгенерируй план для ученика X», «черновик комментария», массовая генерация следующих шагов по когорте.
  - **Шаблоны комментариев** и bulk-действия по ученикам.
  - Приоритетная поддержка / больше AI-лимитов на орг.

> Цены оставь как понятные плейсхолдеры (например Free — 0, Pro — ~$8–12/мес, Business — «от $X/место» или «Contact us»), вынеси в один конфиг `lib/plans.js`, чтобы владелец легко правил. Точные суммы — на усмотрение владельца; не хардкодь по всему коду.

### J2. Техническая реализация гейтинга
- Единый источник правды о тарифах — `lib/plans.js`: описание планов, лимиты, флаги функций (`essayCoach`, `aiCounselor`, `cleanPdf`, `dashboards`, `whiteLabel`, ...). И UI, и серверные проверки читают отсюда.

## K. Дедлайны и напоминания (двигатель retention)

Продукт для поступления по природе **одноразовый** — юзер уходит после подачи. Дедлайны олимпиад/конкурсов/программ — единственная причина возвращаться **по расписанию**. Это ключ к удержанию.

### K1. Структурированные дедлайны в каталоге
- Сейчас у возможностей в `lib/competitions.generated.js` есть только текстовый `season` («Apply by Jan», «Nov & Feb») — **машиночитаемых дат нет**. Добавь опциональные поля даты в схему: например `deadlines: [{ label, date | month, recurring: true }]` (некоторые ежегодные/повторяющиеся, у части — только месяц, у части — точная дата). Заполни для самых важных возможностей; где точной даты нет — оставляй месяц/сезон и помечай как приблизительную. **Никогда не выдумывай точные даты** — если не уверен, ставь месяц + пометку «verify with source» (у продукта уже есть дисклеймер про проверку у источника — держи ту же честность).
- Каталог большой — не обязательно проставлять всё вручную. Сделай так, чтобы поле деградировало: нет `date` → показываем `season`-строку без напоминания.

### K2. Календарь/лента дедлайнов (in-app, делаем сейчас)
- Экран/секция «Мои дедлайны»: возможности, которые ученик **добавил себе** (кнопка «Отслеживать дедлайн» на карточке в `/discover` и в AI-рекомендациях), отсортированные по ближайшей дате, с бэйджами «через N дней». Хранение — в портфолио/Firestore (`portfolios/{uid}.trackedDeadlines` или отдельная коллекция).
- Плюс общий «предстоящие в этом сезоне» вид по всему каталогу с фильтрами (как в `/discover`).
- Из AI-фидбека и AI-канслера, когда рекомендуется конкурс с дедлайном, — сразу кнопка «добавить в мои дедлайны».

### K3. Доставка напоминаний (напиши каркас, но требует настройки — вынеси в отчёт)
- **Реальная отправка** (email / Telegram-бот) требует внешнего сервиса + расписания (cron), а серверлесс сам по себе не «звонит будильником». Это НЕ делается за один заход без setup. Поэтому:
  - Сейчас сделай **in-app напоминания** (бэйджи «дедлайн через 7 дней» при заходе) и подготовь модель данных под внешние уведомления (у юзера — канал: email из аккаунта и/или Telegram chat id, настройки «за сколько дней напоминать»).
  - Опиши в отчёте варианты доставки и что для них нужно: (a) **Vercel Cron** (бесплатно на Hobby, 1 job/день) → серверный роут раз в день читает предстоящие дедлайны и шлёт письма через бесплатный email-провайдер (Resend free tier) — **рекомендуемый путь**; (b) **Telegram-бот** (бесплатно, лучше заходит в СНГ) — бот + вебхук, юзер привязывает аккаунт через `/start <token>`. Не подключай их без ключей владельца — оставь готовые «розетки» (env-переменные, заглушки роутов) и пошаговую инструкцию.
- Напоминания по дедлайнам — хорошая фича и для Free (базовое удержание всем), и усиленная для Pro/Business (кастомные интервалы, дайджест ментору по когорте). Не прячь базовое напоминание за платную стену.

### K4. Связь со стратегией (учти в UX)
- Целевая аудитория смещается на **9–10 классы** (планируют за годы вперёд) — для них дедлайны и многолетний план ценнее «оценки на финише». Поэтому лента дедлайнов должна уметь показывать и «в этом году», и «на будущие годы» (recurring-возможности), чтобы младшие видели горизонт.

## Критерии готовности (проверь перед завершением)
- Приложение собирается (`npm run build`) без ошибок; localStorage-only режим (без Firebase-env) по-прежнему работает.
- AI-роуты возвращают дружелюбный 429 при превышении лимита, а не падают.
- **Тарифы работают:** базовые AI-ревью/полишинг бесплатны (с лимитом); AI-канслер, коуч по эссе, чистый PDF, кастомный share — за Pro; дашборды/white-label — за Business. Гейтинг проверяется **на сервере**, обходится ли клиентский замок — нет.

- Ученик может: создать портфолио, использовать бесплатное AI-ревью/полишинг, подключиться к counselor’у по коду, включить публичную ссылку, скачать PDF, получить разбор эссе и пообщаться с AI-канслером (демо/Pro).

- Ученик видит своего ментора и может отключиться; данные не текут между оргами.
- Лендинг: крутой hero с мини-анимациями (уважает `prefers-reduced-motion`), отлично выглядит на мобиле, говорит с двумя аудиториями, содержит блок прайсинга с 3 тарифами и «попробовать бесплатно».
- Созданы/обновлены: `lib/plans.js`, `firestore.rules`, `CONTENT.md`, и **отчёт с ручными шагами для владельца** (env-переменные: `FOLIO_ADMIN_EMAILS` и, если нужно, service-account для сервера; вставка правил; выставление планов; ориентиры по ценам).
